## The substrate

Hartonomous is one content-addressed universal substrate. Every byte of every digital artifact — Unicode codepoints, text in any script and language, audio frames, image patches, video frames, application telemetry, stack traces, chess PGN moves, DNA sequences, MIDI scores, `config.json` values, tokenizer vocab entries, model card README files, and every per-row signal in every tensor of every ingested safetensors model — decomposes into a Merkle DAG of:

- **Atoms** — content-addressed via BLAKE3 over content bytes alone (`ComputeHash`).
- **Compositions** — content-addressed via Merkle hash over ordered child hashes (`ComputeMerkleHash`).
- **Typed n-ary edges** — content-addressed via `(edge_type_id, role-ordered participant hashes)` (`ComputeEdgeHash`).
- **4D geometry** — every atom and composition has a POINTZM / LINESTRINGZM / MULTILINESTRINGZM / POLYGONZM / MULTIPOINTZM / GEOMETRYCOLLECTIONZM realization in shared `geometry(GeometryZM)` physicality. Per-partition CHECK constraints declare what the four 53-bit mantissa axes encode at this tier of this modality.
- **Per-arena Glicko-2 ratings** on every entity and every edge, with `attestation_type` distinguishing what kind of evidence (corpus, model, lexicon, outcome) drove the rating event.
- **Reference + junction infrastructure** carrying bounded-cardinality vocabularies (`pos`, `language`, `entity_type`, `edge_type`, `provenance`, `significance_context`, `attestation_type`, etc.) and per-entity classifications (`entity_classification`, `entity_pos`, `entity_language`, `codepoint_property`, etc.).

The substrate is **modality-agnostic** (text, audio, image, video, telemetry, sequence data, model weights all decompose to the same atom/composition/edge/geometry vocabulary), **architecture-agnostic** (BERT, Llama, Qwen, Mistral, Phi, Gemma, BART, T5, CLIP, BLIP, Flamingo, Florence-2, FLUX, SDXL, Whisper, MusicGen, Conformer, Swin, DINOv2, SigLIP, DETR, YOLO all decompose via 4 primitives + ~13 tuples), **precision-agnostic** (BF16 / F32 / F64 / AWQ-Q4 / GGUF / FP8 decode losslessly into the same substrate state — quantization variants fire `model_quantization_variant_evidence` attestations stacking on the same edges with lower per-event weight), and **source-agnostic** (the same content from Wikipedia, WordNet, Wiktionary, Tatoeba, a research paper, a user prompt, and a model's tokenizer collapses to one entity by content hash).

It's bounded by **distinct content**, not total content. The same sentence in 10,000 documents is one entity. The same `the` codepoint appearing in 10^12 contexts is one entity with one centroid referenced from every parent composition by hash. The substrate's truth grows quantitatively with every ingested source: cross-source corroboration fires separate `attestation_type`-distinguished rating events on the same edge hash; sigma tightens; mu refines toward consensus.

## The four pillars expressed as schema

| Concept | Storage | Identity |
|---|---|---|
| Atoms + compositions | `substrate.entity(hash)` | `hash` IS the identity; no surrogate `id`; no `entity_type_id` column on entity |
| Structural classification | `substrate.entity_classification(entity_hash, entity_type_id, provenance_id)` | one entity carries multiple classifications without fragmenting identity (e.g. `dog` is both `word_form` and `lemma`) |
| Typed n-ary relations | `substrate.edge(edge_type_id, hash)` + `substrate.edge_member(entity_hash, edge_role_id, role_position)` | edge hash = `(edge_type_id, role-ordered participant hashes)`; edge `geom` = LINESTRINGZM through participants' centroids in role order |
| Universal 4D geometry | `substrate.physicality(physicality_type_id, entity_hash, content_hash, geom geometry(GeometryZM))` | partitioned by `physicality_type_id`; GiST-indexed via `gist_geometry_ops_nd`; operators dispatch through `substrate.st_4d_*` / `substrate.st_s3_*` (raw PostGIS `ST_Distance`/`ST_Centroid`/`ST_FrechetDistance`/`ST_HausdorffDistance` drop dimensions and are forbidden on substrate physicality) |
| Per-arena ratings | `substrate.entity_significance(context_type_id, entity_hash)` + `substrate.edge_significance(context_type_id, edge_type_id, edge_hash)` | every attestation fires a Glicko event; sign-aware (negative correlation = `score=0, weight=|value|`); cross-source corroboration fires separate `attestation_type`-distinguished events on the same row |
| Junction Glicko | `entity_pos(entity_hash, pos_id).mu` + `pattern_deprel(entity_hash, deprel_id).mu` | confidence of classification, distinct from edge trust |
| Reference + junction infrastructure | `entity_type`, `edge_type`, `pos`, `language`, `provenance`, `significance_context`, `attestation_type` + `entity_classification`, `entity_language`, `codepoint_property`, etc. | bounded vocabulary, rebuildable from seeds, microsecond JOIN, NOT substrate content |

Placement metadata (position, ordinal, filename, tensor name, source offset, model id, line number) NEVER enters the hash. It lives on `substrate.sequence`, on typed edges (`has_source`, `in_model`, sequence position), on model-source tables, or on provenance. Same content in two places is one entity with two edges.

## The standard — every model architecture is forced into canonical form

Architectures conform TO the substrate; the substrate does NOT conform to architectures. The canonical form has:

- **4 primitives** — `Linear` (`y = W·x + b`), `LocalKernel` (conv / windowed-bias), `Normalization` (`γ·(x−μ)/σ + β`), `Lookup` (row-indexed retrieval from a learned table).
- **~13 tuple shapes** — `AttentionBlock`, `CrossAttentionBlock`, `SwiGluFfn`, `BertFfn`, `MoeRouterBlock`, `LoraDelta`, `ConvResidualBlock`, `ConformerBlock`, `SwinWindowAttn`, `PatchEmbed`, `DetectionHead`, `EmbeddingLookup`, `BnState`, `VaeAttnBlock`.
- **Per-architecture `TupleResolver` tables** — declarative DATA (not code) mapping each architecture's name dialect to `(PrimitiveKind, ArchetypeTuple, TupleSlot, LayerIdx?, HeadIdx?, ExpertIdx?, ModalityHint, AdaptationOf?)`. BERT's `encoder.layer.0.attention.self.query.weight`, Llama's `model.layers.0.self_attn.q_proj.weight`, Florence-2's `vision_tower.0.0.channel_block.channel_attn.fn.qkv.weight` (fused), FLUX VAE's `encoder.mid.attn_1.q.weight` (`[d,d,1,1]` 1×1 conv reshaped to Linear), canary-qwen's `llm.base_model.model.model.layers.0.self_attn.q_proj.{base_layer, lora_A.default, lora_B.default}.weight` (LoraDelta over a base Linear) all resolve to AttentionBlock-Q (or LoraDelta wrapping it). A new HuggingFace architecture is a table row, not a new decomposer file.

The decomposer library is ~9 source files: 4 PrimitivePasses + 5 TuplePasses + the resolver. The synthesizer library is ~7 files: 4 PrimitiveSynthesizers + 3 TupleSynthesizers. Per-architecture handling lives in DATA.

## Safetensors-in: what the substrate gets

1. **`SafetensorsContainerDecomposer`** reads the `.safetensors` file (and `.pt`/`.bin`/`.ckpt` variants via `IDonorPackageReader`), inventories tensors, handles HF cache / snapshot / multi-component layouts (`model_index.json` for FLUX, Stable Diffusion, Diffusers packages), and dispatches metadata files through their decomposers (`ModelConfigDecomposer`, `ModelIndexDecomposer`, `TokenizerConfigDecomposer`, `ModelCardDecomposer`).
2. **`HuggingFaceTokenizerDecomposer`** reads `tokenizer.json` (BPE / WordPiece / SentencePiece variants); for each vocab byte string it routes through `SubstrateTextDecomposer.EmitStatic` to get / create the `word_form` content entity. The same vocab token across two models that share it collapses to one entity by content hash.
3. **`TupleResolver`** classifies each tensor by `(PrimitiveKind, ArchetypeTuple, TupleSlot, indices, ModalityHint, AdaptationOf?)` from the per-architecture name-pattern table.
4. **PrimitivePasses + TuplePasses** dispatch on the classification. Ingestion is **direct weight decomposition**, not activation-based observation — the trained tensor's own |x| distribution IS the activation pattern; no synthetic prompts, no "tickling," no running inputs through the model to see what fires. The math the tensor's geometry defines (Q^T·K projection for attention; FFN response; embedding row cosine; conv kernel response) is computed directly on the tensor values, and the substrate stores whatever survives the per-tensor adaptive noise floor.
   - **Track 2 transformation tensors** (FFN rows, attention Q/K patterns, attention V/O patterns, MoE expert neurons, MoE router rows, LoRA rank components) fire **typed attestation EDGES between existing content entities** — typically two `word_form` tokens the unit binds (resolved through the model's tokenizer), or one token and a `visual_concept` / `pixel_region` / `audio_chunk` for cross-modal models. The `edge_type_id` (`model_attention_pattern`, `model_ffn_factor`, `model_concept_similarity`, `model_cross_modal_pattern`, `model_spatial_pattern`, etc.) encodes the relationship; the `attestation_type` (`model_attention_qk_pattern`, `model_attention_vo_pattern`, `model_ffn_full_path`, `model_moe_router`, `model_moe_expert_response`, `model_lora_adapter_evidence`, `model_cross_modal_alignment`, `model_local_kernel_evidence`, `model_position_embedding`, `model_input_embedding`, etc.) encodes the evidence kind; the edge's `LINESTRINGZM` trajectory IS the unit's spectral fingerprint. Initial Glicko mu derives from the tensor math itself (projection magnitude, kernel response, activation norm) — not from prompt observation. Sign is preserved as Glicko `score` (positive correlation → `score=1, weight=|value|`; negative correlation → `score=0, weight=|value|`; below-per-tensor-noise-floor → no event, honest abstention). Every pair whose score is above the per-tensor floor becomes an attestation edge; every pair whose score is below floor is gradient-descent jitter and produces no edge.
   - **Embedding tensors** emit one POINTZM **firefly** per token into the substrate's 4D physicality jar, attached to the existing `word_form` entity for that token. Projection: k-NN graph over rows → normalized graph Laplacian → top-3 non-trivial eigenvectors at `λ_2, λ_3, λ_4` → Gram-Schmidt orthonormalization → row's pre-normalization L2 norm as the salience M coordinate. Each ingested model's eigenmap output is in that model's own basis; **anchor-token Procrustes alignment** (Kabsch SVD) maps the new model's anchor fireflies onto the substrate's canonical anchor positions in `substrate.embedding_alignment_anchor` so that post-alignment fireflies share a frame. Token-pair `model_input_embedding` attestations on `model_concept_similarity` edges also fire above the per-tensor noise floor (sign-aware).
   - **Normalization tensors** (γ, β) attach as physicality contour on the parent tensor entity; the BnState (running stats) component is recorded with lower per-event weight via `model_inference_state_evidence`.
   - **Sparse honest recording (Lottery Ticket)**: the discrimination is threshold-only against the per-tensor adaptive noise floor — not top-K. Empirically pre-trained transformers carry ~10–40% real signal and ~60–90% gradient noise (Chen et al. 2020 for BERT; AWQ shows 1% salient channels in large LLMs); the substrate stores the winning ticket (every value above the tensor's own jitter floor) and discards the jitter (every value below). Top-K would arbitrarily truncate real signal at a count cutoff and keep noise just because it made the count — the substrate uses neither. Cross-model corroboration (multi-source LTH): when N models attest the same edge, sigma tightens toward universal-ticket consensus; `games = 1` edges keep wide sigma until disambiguation.
5. **Cross-model corroboration** is automatic: when a second model decomposes into the same `(edge_type_id, role-ordered participant hashes)`, it produces the same edge hash and fires a separate `attestation_type`-distinguished rating event on the **same** edge row. Sigma tightens; mu refines toward consensus; no duplicate edges spawn. The substrate accumulates a strictly more authoritative model of its content than any single ingested source.

Phantom per-role-unit entity types (`attention_head`, `ffn_neuron`, `embedding_position`, `attention_pattern`, `moe_expert_neuron`, `lora_component`, `conv_filter`, `bbox_projection`, `class_projection`, `svd_rank_component`, `codec_codevector`, etc.) are deprecated by the 2026-05-08 architectural correction (`sql/schema/seed/entity_type.sql:59-98`). They fragment cross-model consensus into per-source debris because their identity hashes over per-tensor-row content never collapse across models. New code emits attestation edges between existing content entities. Working template: [`src/Hartonomous.Decomposers/Safetensors/Passes/TokenAttentionEdgePass.cs`](../../src/Hartonomous.Decomposers/Safetensors/Passes/TokenAttentionEdgePass.cs).

## Safetensors-out: Build-a-bear synthesis

`IRecomposer<SafetensorsFile>.RecomposeAsync(TargetArchitectureSpec, RecompositionOptions, CancellationToken)` returns a standard `.safetensors` file loadable in HuggingFace transformers / vLLM / llama.cpp without modification.

`TargetArchitectureSpec` is fully arbitrary. Layer count, hidden dim, attention head count and dim, FFN intermediate size, MoE expert count and routing, LoRA ranks, vocab size, tokenizer choice, modality mix, attention bias style (RoPE / ALiBi / learned), normalization style (LayerNorm / RMSNorm), activation function (SiLU / GELU / ReLU / GeGLU / SwiGLU). "MiniLM-as-MoE-with-Flux" is a valid input. Architectures the substrate has never seen during ingestion are valid inputs; the substrate's content-addressed consensus has no notion of "this architecture is supported."

`RecompositionOptions` carries arena weighting (which arenas weight the consensus), significance threshold (below which attestations don't contribute), source filter (restrict to a subset of ingested models — single-source filter is the degenerate round-trip distillation case), output dtype, and recipe identifier for audit trail.

The recomposer enumerates the target's tuples; for each tuple, dispatches to the appropriate TupleSynthesizer which orchestrates PrimitiveSynthesizers; each PrimitiveSynthesizer reads cross-source consensus from substrate edges (filtered by arena and threshold), projects into the target tensor basis (low-rank approximation `min ‖S − QK^T‖²` over the sparse attestation matrix for `AttentionBlock`; KV-memory inversion for FFN; PCA / inverse Laplacian eigenmap over per-token attestation participation or per-token firefly cluster centroids for embeddings), and writes the target tensor's rows. **Honest abstention**: under-attested cells stay at exact zero with coverage metadata. The recomposer never invents weights to cover gaps. The output is denser-than-jitter (no gradient noise stored), stronger-than-any-single-source (multi-model corroboration tightens consensus), and signed (negative consensus produces negative cell values via the symmetric-around-1500 mu-to-cell transform).

The pre-correction `SafetensorsRecomposer.AssembleTensorBytesAsync` (`src/Hartonomous.Recomposers/SafetensorsRecomposer.cs:239-373`) walks `has_constituent` children of each tensor (the phantom per-role-unit entities) and scatters their stored contours into target rows — single-source phantom-scatter, no consensus, no Build-a-bear. It is on the removal path; the synthesis library replaces it.

## Arenas — open vocabulary tournaments

`substrate.significance_context` is open vocabulary. Starter codes ship in `sql/schema/seed/significance_context.sql` — `lexical_disambiguation`, `syntactic_role_fitness`, `translation_quality`, `model_trust`, `source_authority`, `semantic_relevance`, `corroboration_strength`, `frequency_significance`, `attention_pattern_confidence`, `morphological_productivity`. Practitioners add their own at runtime: `pragmatic_register`, `English-medical-pharmacology`, `Qwen3-vs-Llama3-attention`, `arXiv-2024-vs-textbook-2010`, `Python-stdlib-idiomatic`, whatever tournament they want to run.

Every entity and every edge carries independent Glicko-2 ratings in every arena. New arenas added later auto-backfill into existing edges via substrate functions. Code that hardcodes the starter list is wrong — the pipeline's edge-significance priming cross-products against whatever arenas exist at insert time, with no WHERE filter on context code.

This is how the substrate **competes on equal ground** with any individual model in the practitioner's arenas. Ask the substrate the same question you'd ask Llama or GPT under arena `English-medical-pharmacology`, get back a path through edges weighted by every ingested model's attestations (Llama, GPT, BERT, MiniLM, Florence, plus the practitioner's domain corpus) in that arena's Glicko mu. The substrate has accumulated every ingested model's contribution PLUS the practitioner's corpus PLUS closed-loop Glicko learning from outcomes. The arena's leaderboard at query time IS the answer.

## The loop

**Ingest** (`src/Hartonomous.Decomposers/`) records all candidates without disambiguation. Same input + same decomposer version = byte-identical substrate state (Law #6). All hashing via `Hartonomous.Core.Compute.Common.Blake3` → `Blake3Native`. `MKL_CBWR=AUTO,STRICT` enforced at process start. PRNG seeds declared on decomposer config. BF16 / F32 / F64 / AWQ / GGUF / FP8 decoded losslessly into f64 internally. No approximation methods (HNSW, LSH, ANN, randomized SVD, stochastic estimation, sampling, quantization-as-storage) on substrate content. Sparsity is honest non-storage — per-tensor adaptive noise floor decides what's signal; anything below floor is exact zero on recompose; Lottery Ticket gradient jitter is never stored. All text-bearing content from any decomposer routes through `Hartonomous.Core.Text.CanonicalTextDecomposer.Emit` (seed-uses-core): WordNet glosses, Wiktionary citations, UD sentences, Tatoeba examples, safetensors config JSON values, image captions, audio transcripts, user prompts, model outputs collapse to one `text_composition` per content.

**Infer** (`src/Hartonomous.Engine/`) — the prompt is content too, decomposed by the same text path with `user_session` provenance; its entities ARE the traversal seeds. A\* over typed edges via `ext/hartonomous_pg/src/pg_traversal.c`'s `pg_traverse_astar` with `cost = 1/mu` from `substrate.edge_significance` in the requested arena. The walk consults other queryable surfaces over the same substrate where they help — Voronoi consensus over per-token firefly clouds quantifies cross-model agreement on a token's hidden-space identity; Fréchet matching against stored edge `LINESTRINGZM` trajectories surfaces relations with geometrically similar shape (analogy completion `gender_correspondence(king, queen) ≈ gender_correspondence(man, woman)`; frayed-edge detection; application-fault pattern matching; security-signature matching across telemetry); recursive Merkle centroids place compositions in 4D space; Hausdorff over firefly clouds quantifies cross-model divergence. Output is a new session-scoped composition entity with full explanation trace as substrate content — the path traversed, the Glicko scores at each step, the provenance of each contributing entity and edge, the arena context. The path IS the explanation. Honest abstention where evidence is thin: structured `{ Paths: [], NodesVisited: N, Elapsed: T }`, never fabrication.

The **Gödel Engine** is the substrate's reasoning system / task orchestrator / message queue — it asks questions of itself, reasons of itself, tells itself to do stuff, processes its own task queue, and uses inference / generation / traversal / frayed-edge surveys / ingestion as the tools that execute its decisions. Other substrate components subscribe to the message queue; updating substrate records is one such subscriber. Detailed pub/sub mechanism in `docs/specs/engine/godel-engine.md` and the engine source. It operates at three OODA scales using the same loop: **micro** (per-traversal-step inside a single query — observe available edges, orient via mu / POS / sense / fraying, decide which edge to traverse, act = step); **meso** (per-query — sub-question decomposition into a tree of sub-traversals, partial-result synthesis, contradiction-resolution, retry-with-reflection, clarifying-question surfacing); **macro** (practitioner-scheduled exploration — frayed-edge surveys scoped by edge type / frontier region / significance tier, impact analysis on candidate gaps, source selection from the corpus registry, long-horizon goal progression). CoT, ToT, ReAct, Reflexion, Self-Consistency, GoT, hypothesis-driven reasoning (cross-domain trajectory matching surfacing structural analogies as frayed edges with `cross_domain_analogy` provenance) all emerge from the OODA structure at the appropriate scale — not bolted on, not separately engineered.

Subservience boundaries: the practitioner initiates (tasked mode) or schedules (scheduled mode); macro-level Act (actual ingestion of new sources) has a human-approval gate that is removable but currently in place; cost budgets cap each macro cycle; engine-directed ingestion carries distinct `godel_engine_directed` provenance for audit; long-horizon goal queue is bounded; the engine does NOT self-modify code / heuristics / schema. Within those bounds the engine IS a sophisticated orchestrator — recursive self-questioning, metacognition, hypothesis formation, structurally-informed retry are first-class capabilities, not autonomy violations.

**Synthesize** (`src/Hartonomous.Recomposers/`) — Build-a-bear from cross-source consensus per the safetensors-out section above. Same dispatch model for other modalities once their content decomposers ship: text recomposition walks `text_composition` trees; audio recomposition walks `audio_recording → audio_chunk` LINESTRINGZMs and emits PCM; image recomposition walks `pixel_region` compositions; video recomposition walks per-frame compositions. The same substrate, different output formats.

**Learn** — outcomes (user accept / reject, downstream task succeed / fail, measurable utility) create comparison events between selected and rejected paths; Glicko-2 fires on the corresponding `entity_significance` and `edge_significance` rows via the C kernel `hartonomous_glicko2_bulk_update` (`ext/libhartonomous/src/glicko_bulk.c`). Closed-loop learning without training, gradient descent, or labeled data — Glicko-2 is a tournament model and every use is a comparison event. Junction Glicko (`entity_pos.mu`, `pattern_deprel.mu`) updates the same way.

## Two product surfaces from one substrate

- **Build-a-bear** — the user specifies an arbitrary target architecture and gets a `.safetensors` file synthesized from cross-source consensus, sparse where the substrate honestly abstains.
- **Crystal ball** — substrate state is queryable as SQL for mechanistic interpretability (induction-head shape across N models), bias / safety audit (consensus between sensitive-attribute tokens and outcome tokens), capability tomography (per-domain attestation density per model), hallucination diagnosis (per-edge mu density along an inference path), provenance / contamination / theft detection (attestation fingerprint similarity), marketplace economics (per-model novelty contribution), cross-model architectural diff, frayed-edge atlas. No separate analytics product — the substrate IS the analytics surface.

Both products are emergent from getting the ingestion shape right.

## Why this category — the Familiar Principle

This category of system has no industry name because the industry hasn't built it. The Western magical tradition has the word *familiar*. Hartonomous is one. Property 1: **bonded to a specific practitioner** — local-first execution; CPU-only inference (AVX2+FMA3+AVX-VNNI+BMI2 consumer-CPU ceiling, not AVX-512 datacenter); PostgreSQL-only storage on the practitioner's own machine; no cloud sync. Property 2: **subservient, not autonomous** — substrate emits paths and rated edges (the raw traversal record) and recomposer output (deterministic reconstruction or arena-weighted synthesis), not probability distributions; the practitioner decides what to do with the output. Property 3: **auditable by the master** — every Glicko rating, every provenance, every significance score, every firefly coordinate is a row the practitioner can `SELECT`, diff across time, override. The substrate has no interpretability problem because it has no hidden layer; it is interpretable by construction. Property 4: **learns from service** — Glicko-2 ratings update on use, specific to the practitioner's queries / corrections / corpora. A substrate used by a biologist and a substrate used by a lawyer, starting from the same seed, develop different rating distributions. Property 5: **goes places the practitioner cannot** — they cannot realistically train a 70B-parameter transformer; they can ingest one. The safetensors decomposer extracts the learned attestation surface into the shared substrate; from that moment on, the familiar carries what the model learned without needing to run the model.
