# ISO 639 Decomposer Specification

## Identity

- **Decomposer class**: `Iso639Decomposer` extends `BaseDecomposer`
- **Source path**: `D:\Models\ISO639\iso-639-3.tab`
- **Trust prior**: Authoritative (SIL International / ISO standard)
- **Provenance**: `sil/iso-639-3`
- **Dependency**: Phase 2a (UCD/UCA must be seeded first -- language names contain codepoints that must already exist as tier-0 entities)

## What This Decomposer Creates

Language identity as **reference table rows**. Every language known to ISO 639-3 becomes a row in the `language` reference table. Language codes are the canonical identifiers that all subsequent decomposers (WordNet, OMW, UD, Wiktionary, Tatoeba) use to tag content by language via the `entity_language` junction table. Without this decomposer, nothing can be language-tagged.

Language reference names (e.g., "Arbëreshë Albanian") are also created as composition entities in the entity table — these are substrate content. But the language codes themselves are infrastructure.

## Source Format

Tab-separated, 7,928 rows (confirmed from data), UTF-8. Header row followed by data rows.

### Columns (8 total, confirmed)

| Column | Description | Example |
|--------|------------|---------|
| `Id` | ISO 639-3 three-letter code. Primary identifier. | `eng`, `cmn`, `fra`, `deu` |
| `Part2b` | ISO 639-2/B bibliographic code (if exists). | `fre` (for French) |
| `Part2t` | ISO 639-2/T terminological code (if exists). | `fra` (for French) |
| `Part1` | ISO 639-1 two-letter code (if exists). | `en`, `zh`, `fr`, `de` |
| `Scope` | I=Individual, M=Macrolanguage, S=Special | `I`, `M`, `S` |
| `Language_Type` | L=Living, E=Extinct, A=Ancient, H=Historical, C=Constructed, S=Special | `L`, `E`, `A`, `H`, `C` |
| `Ref_Name` | Reference name of the language. | `English`, `Ghotuo`, `Arbëreshë Albanian` |
| `Comment` | Optional notes. Usually empty. | |

### Empty fields

`Part2b`, `Part2t`, `Part1`, and `Comment` are frequently empty. Of 7,928 languages, only ~184 have Part1 codes, ~485 have Part2b/Part2t codes. Most languages have only the Id, Scope, Language_Type, and Ref_Name.

## Entity Model

Each language populates a row in the `language` reference table. Language reference names are created as composition entities in the entity table.

```
-- Reference table row (the primary output):
language: code='eng', part1='en', part2b='eng', part2t='eng',
          scope='Individual', language_type='Living',
          ref_name='English'

-- Reference table row (minimal — most languages):
language: code='aae', part1=NULL, part2b=NULL, part2t=NULL,
          scope='Individual', language_type='Living',
          ref_name='Arbëreshë Albanian'

-- Entity table row (language name as substrate content):
entity: hash=BLAKE3('English'), entity_type_id→entity_type('language_name')
entity: hash=BLAKE3('Arbëreshë Albanian'), entity_type_id→entity_type('language_name')
  sequence: [A, r, b, ë, r, e, s, h, ë, ' ', A, l, b, a, n, i, a, n]
  -- includes U+00EB (LATIN SMALL LETTER E WITH DIAERESIS) from UCD

-- Link from reference table to entity (FK on the language table, not an edge):
-- language.name_entity_id FK → entity(id) for 'Arbëreshë Albanian'
-- Edges connect entities to entities; reference table rows are not entities.
-- The ref_name column stores the text, name_entity_id points to the decomposed composition.
```

Shared values:
- Scope values ("Individual", "Macrolanguage", "Special") are columns on the `language` reference table, not separate entities. ONE column value shared by ~7,500+ languages.
- Language type values ("Living", "Extinct", "Ancient", etc.) same — column values.
- The language name IS a composition entity because it contains codepoints. "Arbëreshë Albanian" decomposes into codepoints including U+00EB, which must already exist from Phase 2a UCD seed.

## Reference Table Schema

The `language` reference table holds all ISO 639-3 data as columns:

| Column | Type | Purpose |
|--------|------|---------|
| `id` | `SERIAL` | Surrogate key for FK efficiency. |
| `code` | `VARCHAR(3) UNIQUE` | ISO 639-3 three-letter code. |
| `part1` | `VARCHAR(2)` | ISO 639-1 two-letter code (NULL if absent). |
| `part2b` | `VARCHAR(3)` | ISO 639-2/B bibliographic code (NULL if absent). |
| `part2t` | `VARCHAR(3)` | ISO 639-2/T terminological code (NULL if absent). |
| `scope` | `VARCHAR` | I=Individual, M=Macrolanguage, S=Special. |
| `language_type` | `VARCHAR` | L=Living, E=Extinct, A=Ancient, H=Historical, C=Constructed, S=Special. |
| `ref_name` | `VARCHAR` | Reference name of the language. |
| `name_entity_id` | `BIGINT FK → entity(id)` | The decomposed language name entity (composition of codepoints). NULL until entity is created. |

## Physicality

Each language name entity gets:
- LINESTRINGZM trajectory from the codepoint positions of its ISO 639-3 code (e.g., "eng" trajectory through S3 positions of e, n, g).
- Centroid of that trajectory as the name entity's own position.

## Significance

Initial trust prior: Authoritative. ISO 639-3 is a maintained international standard.

## Analysis Passes

- `MacrolanguageExpansionPass` -- for Scope=M languages, identify which individual languages they encompass (requires external macrolanguage mapping data if available)
- `CodeCrossReferencePass` -- verify Part1/Part2b/Part2t consistency across entries
- `NameDecompositionPass` -- decompose reference names into substrate codepoint compositions with morphological analysis where the seed data supports it

## Completeness Criteria

- All 7,928 languages have rows in the `language` reference table.
- All non-empty fields populated as columns (Part1/Part2b/Part2t NULL where absent — sparsity).
- All language reference names are decomposed into codepoint composition entities (not stored as opaque strings).
- Scope and Language_Type values are columns on the reference table (not duplicated as separate entities).
- Part1/Part2b/Part2t cross-references are validated for consistency.
- Every subsequent decomposer can reference these language rows for language-tagging via the `entity_language` junction table.
